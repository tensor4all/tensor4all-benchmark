# result/

One directory per (hardware profile, measured tensor4all-rs revision), each
holding one complete sweep of the three maintained cases:

```text
result/INDEX.md                       generated table of contents over every sweep
result/<profile>/<rev12>/run.yaml     machine, source and tensor4all-rs revision, thread count, CPU set
result/<profile>/<rev12>/raw/*.json   one record per case, arm and instance
result/<profile>/<rev12>/report.md    generated by scripts/report.py from the records above
```

[`INDEX.md`](INDEX.md) is the entry point and links every sweep. `report.md` is
the human-facing page of one sweep; the records behind it are the source of
truth, and they carry the per-instance timings, accuracy against the case
reference, output bond dimensions, allocation counts, and the parameters that
produced them.

A profile name is the machine alone on the reference single-core sweep, plus
`-<n>t` on the optional multithreaded scaling sweep of the same machine. Read a
`-<n>t` profile against that machine's single-core profile, never instead of it.
Measuring a new revision adds a directory rather than replacing one, so the tree
keeps the history the index links to; re-measuring the same revision replaces
that one directory.

Regenerate a report with `python3 scripts/report.py result/<profile>/<rev12>` and
the index with `python3 scripts/gen_index.py` (`--check` fails instead of
writing). Never edit either by hand.
