# result/

One directory per hardware profile, each holding one complete sweep of the three
maintained cases:

```text
result/<profile>/run.yaml     machine, source and tensor4all-rs revision, thread count, CPU set
result/<profile>/raw/*.json   one record per case, arm and instance
result/<profile>/report.md    generated by scripts/report.py from the records above
```

`report.md` is the human-facing entry point. The records behind it are the
source of truth: they carry the per-instance timings, accuracy against the case
reference, output bond dimensions, allocation counts, and the parameters that
produced them.

A profile name is the machine alone on the reference single-core sweep, plus
`-<n>t` on the optional multithreaded scaling sweep of the same machine. Read a
`-<n>t` profile against that machine's single-core profile, never instead of it.

Regenerate a report with `python3 scripts/report.py result/<profile>`; never edit
one by hand. Historical reports are not maintained, use git history.
